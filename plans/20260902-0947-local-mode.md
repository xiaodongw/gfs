# Local mode: a workspace over a local clone, no server

## Summary

The use case: a developer already has a full clone of a monorepo and wants one
working tree per change, but `git worktree add` copies the whole tree — on this
machine 2.6 s and 302 MiB for vscode, 1.3 s and 75 MiB for django, and worse on a
real monorepo. GFS already presents a pinned commit as a lazy tree; today it can
only do so from `gfs-server`. Local mode lets `gfs-fuse` serve the tree, the
content, the `.git` surface, history, and search directly from the clone's own
object database, with no server, no lease, no shims on `PATH`.

The mount layer named `SnapshotClient` concretely at every call site. The work
is therefore two things: an adapter trait that both the gRPC/HTTP client and a
libgit2-backed local source implement, and a local source whose pin, index,
refs, object store, and search come from `gfs-git` instead of the wire. Then a
benchmark that puts local mode beside `git worktree add` and the server mount.

## Plan

**Phase 1 — the adapter seam** (`crates/gfs-mount/src/source.rs`)
* `SnapshotSource`: an `async_trait` with the read surface the mount actually
  uses — entry, batch entries, directory and tree pages, blob bytes, the
  per-commit index, commit metadata, log, resolve, refs, diff, blame, search,
  prepare, lease renew/release — plus three capability hooks with defaults:
  `leased()`, `serves_blobs_in_memory()`, `capability_for_persistence()`.
* `SnapshotClient` implements it. The shared value types (`MountBinding`,
  `DirectoryPage`, `TreePage`, `LogQuery`, `DiffQuery`, `RevDiff`, `Blame`)
  move to `source.rs`; `client.rs` becomes one implementation.
* Every `Arc<SnapshotClient>` in `fs`, `prefetch`, `cache`, `blobs`, `search`,
  `mount`, and the test harness becomes `Arc<dyn SnapshotSource>`.
* The index download moves from `OdbClient` onto the source, since it is a
  per-commit artifact rather than a per-repository one.
* Pure refactor: the suite must pass unchanged.

**Phase 2 — the local source** (`crates/gfs-mount/src/local.rs`)
* `gfs-mount` gains `gfs-git`. `LocalRepository` opens the clone once per host
  (shared by canonical path, like the odb projection is shared by repository)
  and knows its objects directory.
* `LocalSource` implements `SnapshotSource` over `AsyncRepository`: every
  call is one `spawn_blocking` under the handle pool's admission control.
  Blob tickets are empty; `prepare_snapshot` is always ready; renew/release
  are no-ops; `leased()` is false; `serves_blobs_in_memory()` is true.
* Pinning: `resolve(selector)` gives commit, tree, ref name, and snapshot
  time; a lease anchor `refs/gfs/mounts/<id>` is written into the clone so
  `gc` cannot prune the pin, and deleted at unmount. The mount id is random.
* Index: `index_for_commit` in-process. Refs: `visible_ref_targets`, written
  as `packed-refs` exactly as the remote path does, so `origin/main` and tags
  resolve.
* Object store: no projection. `objects/info/alternates` points at the
  clone's objects directory by absolute path and `.git/gfs/objects` is not
  presented. Stock Git then reads the clone's packs directly, which is what
  `git worktree` does.
* Reads: `FileState::Memory` serves a base blob from bytes held for the life
  of the handle, behind a small per-clone LRU of decompressed blobs, so a
  read never writes a second copy of the file to disk. The hydration budget
  is off for local mounts; nothing crosses a network.
* Search: `LocalSource::search` walks the tree and runs `gfs_search::
  search_local` over chunks of paths in parallel, reading blobs straight
  from the pack. No index, no `SNAPSHOT_BUILDING`; coverage and truncation
  are reported the same way the server reports them.
* The heartbeat is not spawned for an unleased source; health reads
  `Healthy`.

**Phase 3 — surface**
* `MountRequest`, `MountSpec`, and `mount.json` carry `local_clone`.
* `gfs mount --local <clone>`; `--repo` becomes optional and is refused
  alongside `--local`. The report prints `origin  local <clone>`.
* Seeded config in local mode: the fsmonitor hook and the LFS filter stay
  (both answer from the mount, and both are what keep `git status` and
  `git add` honest); no `[remote "origin"]` credential helper; the git and
  scan shims are not installed and not needed.

**Phase 4 — smoke tests** (`crates/gfs-mount/tests/local.rs`)
* Mount a fixture clone in local mode through the in-process host, compare
  the tree with the real-Git oracle, read content, `git status` clean, edit
  and `git commit` with stock Git, `git log`, search finds a known line, the
  anchor ref exists while mounted and is gone after unmount.

**Phase 5 — benchmark** (`spikes/corpus/benchmark-local.sh`,
`benchmarks/local-mode.md`)
* Per corpus repository: `git worktree add` against a real clone, `gfs mount
  --local` against the same clone, and the server mount, on the same step
  list as the agent-workflow benchmark plus a read-through step and a raw
  `rg` over the mount (the no-shim case). Disk after unmount.

**Phase 6 — docs**: README, ARCHITECTURE §1 and a short local-mode section,
ADR 0013.
