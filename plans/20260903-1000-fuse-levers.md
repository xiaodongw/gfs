# FUSE levers: kernel passthrough, writeback cache, prewarm

## Summary
After ADR 0014 a warm local-mode file costs one `open` and one `release`
round trip; a cold one adds a `read` round trip and libgit2's inflate; every
write is a round trip that also commits a journal row. Three levers, one
commit each, each measured against the previous one on the vscode and django
corpora with `spikes/corpus/benchmark-levers.sh`:

1. **Kernel passthrough** (kernel 6.9+, `fuser` 0.18): the daemon registers a
   backing file at `open` and the kernel reads and writes it directly. Base
   blobs get a memfd holding the inflated bytes (local mode) or the cache
   file itself (server mode); overlay files get their content file. Needs
   `CAP_SYS_ADMIN` on the daemon (`setcap cap_sys_admin+ep gfs-fuse`); the
   daemon probes once and falls back to today's path when refused.
2. **Writeback cache** (`FUSE_WRITEBACK_CACHE`): the kernel coalesces small
   writes into page-sized requests. The kernel then owns size/mtime/ctime of
   every regular file, so a file the daemon rewrites behind the kernel must
   come back as a new inode: records carry a generation, bumped at repin.
3. **Prewarm** (`gfs mount --local … --prewarm`): inflate the pinned tree's
   blobs into the blob LRU in the background after mount, so the first
   `rg`/build sees warm costs.

## Plan
- Baseline: `benchmark-levers.sh` on the ADR 0014 build.
- Commit 1: `init` requests `FUSE_PASSTHROUGH` + stack depth 1; `Gfs` keeps a
  bounded LRU of `BackingId`s keyed by blob oid or overlay content id, each
  open handle holds an `Arc` on its backing so an id is never closed under an
  in-flight open; `open`/`create` reply `opened_passthrough`; overlay-local
  records with a live passthrough writer answer `getattr`/`lookup` from an
  `fstat` of the content file; `release` of a writable passthrough handle
  writes the content file's size/mtime back into the journal
  (`Overlay::refresh_content`). `SnapshotSource::forget_blob` lets local mode
  drop the `Vec` copy once the memfd holds the bytes. Stats: `passthrough_opens`.
- Commit 2: `init` requests `FUSE_WRITEBACK_CACHE` when `FsConfig.writeback_cache` is set (CLI `--writeback-cache`, through `MountRequest`); `Record.generation`
  replaces the constant; `InodeTable::repin` bumps it for regular files;
  `persist()` bumps `.git/gfs/mount.json` when it is cached.
- Commit 3: `--prewarm` on the CLI → `MountRequest` → `MountSpec`; local
  mounts spawn a walk over `list_tree` that inflates blobs through
  `read_blob_shared` until the LRU is full; progress in `gfs inspect`.
- Each commit: build, `cargo test -p gfs-mount`, run the levers benchmark,
  record in `benchmarks/fuse-levers.md`.

## Decisions
- Passthrough is probed, not configured: the kernel refuses the backing
  ioctl without `CAP_SYS_ADMIN`, and a mount that cannot get it must behave
  exactly as before. The probe result is per mount and sticky, because the
  kernel refuses to mix passthrough and cached opens on one inode.
- One backing id per blob/content file, reused across opens, because the
  kernel refuses two different backing files on one inode (`EBUSY`). The
  known consequence: a copy-up while a reader still holds the base blob's
  backing makes the writer's `open` fail with `EBUSY`; rare, documented.
- Writeback cache is **opt-in** (`gfs mount --writeback-cache`). It was
  going to be the default with the generation mechanism covering the size
  hazard, until the full test run hung in the quota test: under writeback a
  `write(2)` always succeeds into the page cache and the overlay's `EDQUOT`
  only surfaces at `close`. That changes the quota contract (refuse the new
  write, keep the old ones), so the operator has to choose it. The size
  hazard is still handled: `Record.generation`, bumped at repin for regular
  files and by `persist()` for `mount.json`.
- Prewarm is a flag, not a default: it spends CPU and up to the LRU's 256 MiB
  on a tree the job may never read.

## Details
- The passthrough numbers need the capability on the release binary; every
  rebuild drops it: `sudo setcap cap_sys_admin+ep target/release/gfs-fuse`.
- Passthrough writes bypass the overlay quota until `release`, where the
  accounting catches up; the quota is advisory under passthrough.
